## 零、「如何找页面元素」方法论（2026-09-21 沉淀）

> 想给宿主某个界面元素加样式时，怎么确定它在哪、用什么选择器命中。按此顺序排查，不要靠猜。

1. **先想「这是什么功能」再找源码**：在宿主源码 `packages/client/` 下按功能关键词搜组件，
   如「思考」→ `ReasoningRow`、「工具卡片」→ ui-tool `ToolRow`、「排队」→ ui-conversation
   `QueueDock`、「todo」→ todo 面板。搜到组件后**读它的 TSX 渲染结构**，优先找：
   - **语义属性锚点**（data-* / role / aria 属性）——`data-variant`、`data-state`、`data-expanded`、
     `data-testid`、`role` 是开发者明确标注的，**不随 CSS Modules hash 变化**，首选。
   - 结构性容器（根 div、children 区）——配合展开态属性（如 `data-expanded`）做状态区分。
2. **CSS Modules 类名陷阱（本主题多次踩坑）**：宿主 CSS Modules 编译后类名格式是
   `hash_类名`（**前缀 hash + 下划线 + 类名，类名后无下划线**），如 `Y5oNUG_thinkBody`、
   `CBZH9a_markdownPayload`。因此：
   - 想命中「某类名的后代」写 `[class*='_类名']`（无尾下划线）；写 `[class*='_类名_']`（带尾下划线）
     会匹配不到 → **规则静默失效**（曾致思考胶囊不生效）。
   - 多个语义强相关类共用前缀时，类名片段选择器可能误伤（如 `markdownPayload`/`markdownPreview`），
     此时应优先用外层语义属性锚点（data-variant 等）收窄，再配类名片段。
3. **验证规则真的命中**：改完 build 后，若怀疑选择器未命中，直接查打包产物确认类名真实形态：
   ```bash
   grep -rho "[A-Za-z0-9_-]*_thinkBody" <DSH安装目录>/packages/client --include="*.js" | sort -u
   # 例：Y5oNUG_thinkBody → 确认无尾下划线
   或打开页面用浏览器 DevTools 检查元素（Element → 看真实 class 与 data-* 属性）。
4. **状态区分**：折叠/展开、运行中/完成等状态变化，优先用宿主自己的状态属性
   （如 `data-expanded`、`data-state="running|ok"`）做条件，不要依赖「内容出现与否」猜。
5. **不要用 CSS Modules hash 本身**：hash 每次构建会变；前缀类名片段（`[class*='_thinkBody']`）
   与语义属性锚点才是稳定的。
6. **宿主升级后核对**：宿主升级可能改组件结构。对照本表逐条看对应锚点/类名是否仍然存在
   （grep 宿主源码确认），失效的及时替换。

## 一、CSS 选择器覆盖（identity.js）

### 胶囊配方（2026-09-21 沉淀，给宿主任意元素加胶囊先看这）

> 主题「胶囊」= 半透明紫底 + 圆角 + 内边距，白字下衬底不花眼。已应用：AI 回复正文（markdown）、思考展开正文（thinkBody）、状态提示（status）、todo 面板、排队消息条、**工具行摘要（summaryText）**。

- **基础配方**（正文/块级元素，markdown/thinkBody/summaryText 同款）：
  ```css
  [class*='_目标类名'] { background: rgba(var(--mediascape-dsh-theme-bg-layer), 0.5) !important; border-radius: 12px !important; padding: 6px 12px !important; }
  ```
- **选择器写法铁律**：宿主 CSS Modules 编译类名是 `hash_类名`（**前缀 hash + 下划线 + 类名，类名后无下划线**）。命中用 `[class*='_类名']`；写成 `[class*='_类名_']`（带尾下划线）会匹配不到 → 规则静默失效（曾致思考胶囊不生效）。
- **内层子元素**：胶囊内部子元素若叠全局黑描边（`* { text-shadow }`）发糊，补 `[class*='_目标类名'] [class*='_'] { text-shadow: inherit !important; }`。
- **状态胶囊**（行内小胶囊，role="status" 同款）：`display: inline-flex; align-items: center; border-radius: 999px; padding: 4px 14px; background: rgba(124,120,190,0.6)`。
- **何时不加**：折叠态标题行不加胶囊（与 bash 折叠态一致：标题无胶囊，展开内容才有）；若元素本身是用户消息/输入气泡（data-pending-steering / data-submission-echo）禁止加，会误伤。
- **验证**：改完 build 后，若怀疑选择器未命中，直接 grep 打包产物确认类名真实形态（如 `grep -rho "[A-Za-z0-9_-]*_summaryText" <DSH安装目录>/packages/client --include="*.js" | sort -u` → `Y5oNUG_summaryText`），或 DevTools 看元素真实 class。
- **启用开关（2026-09-22）**：胶囊配方每条可带 `enabled`（缺省 true）——`false` 时 capsuleCSS() 跳过该条（不输出 CSS），即「关闭后没有胶囊」。配色盘胶囊 tab 每条头部有「启用」勾选框（`cr-enabled`），勾选状态写回 capsules.json。带 `parent` 字段的规则（如 `flowItem`/`older` → `chatColumn`）在配色盘按父子层级缩进展示（`cr-children` 子容器 + 左边框缩进）。
- **层级注入排序（2026-09-22）**：`capsuleCSS()` 渲染时按 `parent` 关系拓扑排序（深度优先、父先子后、同层保序）——外层（父级）先注入、内层（子级）后注入，同特异性选择器后写覆盖先写 → **子级自然覆盖父级**（层级正确的视觉呈现，无需手工拼优先级）。实测注入顺序：`chatColumn`→`flowItem`/`older`、`tabStrip`→`guide`→`guideEntry`（此前 `guide` 在 `tabStrip` 前为反序，子先父后会被父级覆盖）。

### 聊天消息流主列（ChatView column）层级结构与可胶囊 class 清单（2026-09-22）

> 宿主源码：`packages/client/ui-chat/src/client/chat/ChatView.module.css` + `ChatView.tsx`。
> DOM 结构（column 为 `data-chat-flow` 容器，hash 前缀随构建变，本机当前为 `pOlsGa`）：

```
div.root
└─ div.scroll（滚动容器，全出血 padding）
   └─ div.column[data-chat-flow]（消息主列：居中限宽 max-width: var(--dsh-chat-content-width)）★ chatColumn 胶囊
      ├─ div.hint           加载历史提示（openState='loading' 时）→ 可胶囊（小字提示条）
      ├─ div.openError      加载错误提示（openState='error' 时）→ 可胶囊（红字错误条）
      ├─ div.older > button 「加载更早消息」按钮（hasMore 时）→ ★ older 胶囊（已加）
      ├─ ChatNodeList
      │   └─ div.flowItem   每个消息座（ChatNodeSeat，column 直接子、按 16px 流间距排）→ ★ flowItem 胶囊（已加）
      │        └─ 消息内部已有独立胶囊：markdown（AI 回复正文）/ thinkBody（思考展开）/ summary（工具/思考折叠摘要）
      ├─ TurnStatus（role="status" 运行中状态行）→ 已有 status 胶囊
      ├─ PendingSteeringBubble / PendingSubmissionBubble（排队/提交回显气泡，禁止胶囊：data-pending-steering 是用户消息）
      └─ div.toBottomSlot > button.toBottom（回底部浮动按钮，sticky 定位，禁止胶囊：破坏浮动定位）
```

- **稳定选择器**：column 用 `[data-conversation-scroll] [class$='_column']`，flowItem 用 `[data-conversation-scroll] [class$='_flowItem']`，
  older 用 `[data-conversation-scroll] [class$='_older'] button`——锚点 `data-conversation-scroll` 是 `:global` 属性不随 hash 变、
  类名尾缀（`_column`/`_flowItem`/`_older`）稳定；hash 前缀（pOlsGa 等）每次构建可能变，**不要写进选择器**。
- **capsules.json 现有 chatColumn 组（parent 关系）**：`chatColumn`（整列面板：layer 0.32 + 圆角 16px + padding 10px 14px）→
  子级 `flowItem`（消息座：layer 0.28 + 圆角 12px + padding 8px 12px）、`older`（加载更早按钮：layer 0.3 + 圆角 14px）。
- **可再加但暂未加**（避免过度装饰）：`hint`（加载提示）、`openError`（错误提示）——如需加：选择器 `[data-conversation-scroll] [class$='_hint']` / `[class$='_openError']`。
- **禁止胶囊**：`toBottom`/`toBottomSlot`（sticky 浮动、加底会破坏定位与圆角按钮外观）、PendingSteeringBubble/PendingSubmissionBubble（用户消息/排队气泡，规则见「何时不加」）。

## 五、宿主升级失效风险点

- **CSS Modules hash**：`_float_` / `_mask_` / `_markdown_` 是压缩后类名前缀，宿主升级可能改 hash 结构 → 用属性包含选择器 `[class*='xxx']` 降低失效概率，但语义层（新 UI 框架）升级需重新核对。
- **`role="status"`**：语义锚点，最稳定；若宿主改用别的方式呈现状态提示需重定位。
- **`--dsh-content-font-size`**：宿主公开变量（ui-theme bootThemeScript 定义），升级一般不破坏；若改变量名需同步 font.js。
- **`--dsw-specific-sidebar-fill`**：宿主 ui-theme 令牌名稳定；升级后核对 opacity 语义。
- **行为层**：`ctx.theme` / `data-ds-dark-theme` / colorScheme 挂钩依赖宿主主题 API，升级时先查 ui-theme 是否变更。

## 五·补、配色注入机制对比：颜色区 vs 胶囊区（2026-09-23 实测沉淀）

> 改配色/胶囊前先读这节，知道改完「哪里生效、哪里要同步」。

| 维度 | 颜色区（theme-colors.json → tokens/identity） | 胶囊区（capsules.json → CAPSULES_DATA） |
|---|---|---|
| **注入时点** | **配色盘 apply 时写盘**：`/api/theme-apply` 直接改写 `tokens.js`/`identity.js` 源文件，然后调 build | **build 时读**：build.cjs 每次运行动态读 capsules.json（三级）→ 替换 `/*__CAPSULES_START__*/` 占位符 |
| **build 里读什么** | build 不读 theme-colors.json（只读 `bgLayer.hex` 一个值给胶囊底色兜底）——文件在 apply 阶段被「预烘焙」进 tokens.js/identity.js 片段，build 只按 `PART_ORDER` 静态拼接 | build 读运行态→仓库→内置三级源，读到什么注入什么 |
| **兜底机制** | **无 build 级兜底**——tokens.js/identity.js 缺失则 build ENOENT 崩溃；配色值缺省靠 `pick()` 回退默认色（代码级） | **三级兜底**（运行态→仓库→内置 BUILTIN_CAPSULES），两级都挂也能 build，绝不出空胶囊 |
| **日志** | 无专门 build 日志（apply 有 console.log） | `capsulesLogLine` 写 build-capsules.log：来源/条数/键清单/失败原因 |
| **生效** | apply 改源文件 → build 产物变（下次加载生效） | build 每次读最新胶囊 → 产物变 |
| **可恢复性** | 无备份（靠 git 历史） | 运行态副本损坏 → 自动从仓库复制初始化（自愈） |

**一句话**：颜色区是「apply 时预烘焙进源码」（build 只拼静态文件），胶囊区是「build 时动态注入」（build 实时读三级源 + 内置兜底 + 日志）。

**配套纪律（改配色键必读）**：新增配色元素键要同步改三处——`theme-colors.json`（colors 键）+ `start-preview.mjs` buildTokensContent 生成器 + `tokens.js` 本体；生成器与本体必须一致，否则 build 产物与 apply 后的不一致（曾踩坑）。

## 五·补2、配色盘键名规范：配色区 vs 胶囊区（2026-09-2x 用户定稿）

> 配色盘网站有「配色」和「胶囊」两套独立配置，**都是有效规范、故意区分**——配色只管元素颜色（hex+透明度），胶囊管背景配方（底色+圆角+内边距+附加声明）。改哪个区用哪套键，不要混用。

| 维度 | 配色区（theme-colors.json `colors` + comps.json `key`） | 胶囊区（capsules.json `rules[].key`） |
|---|---|---|
| **作用** | 元素**颜色**（hex + alpha），apply 时预烘焙进 tokens/identity | 元素**背景配方**（bg 底 + radius + padding + extra），build 时注入 capsuleCSS() |
| **键名规范** | **语义名**（kebab-case / 驼峰）：`sidebar-left`、`sidebar-fill`、`sidebar-brand`、`sessionHeader`、`todo-panel`、`dock-bar`、`btn-primary`、`status-capsule` | **语义名**：`markdown`、`thinkBody`、`status`、`todo`、`queue-dock`、`guide`、`guideEntry`、`tabStrip` |
| **层级表达** | 无（每个元素独立键） | `parent` 字段（tabStrip→guide→guideEntry），配色盘按父子缩进展示 |
| **命中宿主** | 生成器消费键 → `--dsw-specific-*` 变量 → identity.js 按稳定锚点应用 | 每条自带 `selector`（稳定锚点 data-* / 类名尾缀） |

**怎么判断键名是否规范**（三步）：
1. **是不是语义名**？键名能描述元素「功能/位置」（如右侧边栏文件树 body → `panelBody`）→ 符合。键名里带机器前缀（CSS Modules hash 如 `_620KBG_`、混淆片段）→ **不符合**——hash 随宿主构建变，应换语义名，并在 selector/desc 里注明真实类名与稳定锚点。
2. **要颜色还是胶囊配方**？只调底色/透明度 → 配色区（theme-colors.json + comps.json，按「五·补」三处同步纪律）；要背景+圆角+内边距的胶囊 → 胶囊区（capsules.json，自带 selector）。
3. **对照现有键风格**：配色区看 `sidebar-*`/`*-panel`/`*-capsule` 系；胶囊区看 `guide`/`guideEntry`/`tabStrip` 系——新键与同区已有键同一风格即规范。

**实例（2026-09-2x 落地）**：右侧边栏「文件」tab 文件树 body——宿主真实类名 `_620KBG_body`（hash 前缀，随构建变），**稳定锚点 `data-files-body="true"`**（宿主 SidebarFiles 容器属性）。
- 配色区键：`panelBody`（语义名，无 hash）→ colors `{"hex":"#362A56","alpha":0.65}` + comps 元素行 + 生成器 `--dsw-specific-files-body` + tokens.js 本体 + identity.js `[data-files-body]{ background: var(--dsw-specific-files-body) }`（只上底色，不加胶囊）。
- 若以后要加胶囊配方：胶囊区键 `filesBody`（语义名）+ `selector: "[data-files-body]"`，与 `guide` 同属右侧边栏家族。

## 六、踩坑教训（避免重蹈覆辙）

| 教训 | 详情 |
|---|---|
| **别用 `data-pending-steering` 做排队气泡样式** | 该属性标记的正是**用户消息气泡本身**（ui-chat MessageItem.tsx UserStyleBubble 的 pending 态），给其加背景/边框 = 用户刚发的消息出现胶囊（发消息时出现、落地后消失）。排队提示若需视觉区分，必须选不命中用户气泡的稳定锚点（如会话流外层容器），禁止直接命中 `[data-pending-steering]` / `[data-submission-echo]`（2026-09 实测误伤回退）。 |
| **开屏视频「消失」多为加载慢而非丢文件** | boot/robin-6s.mp4 约 24MB，首次加载（无缓存）需缓冲，黑块 = 视频加载中；第二次即有缓存秒出。排查顺序：文件本体（ls/xxd ftyp）→ 服务端响应（curl status/size）→ 加载时序，勿先改播放逻辑。 |
| **`[class*='_markdown_']` 只应覆盖 AI 回复正文载体** | 若宿主后续让用户消息正文也走相同 markdown 容器类，胶囊会误伤用户气泡——改前先查宿主该容器类归属（AssistantMarkdown vs UserStyleBubble）。 |
