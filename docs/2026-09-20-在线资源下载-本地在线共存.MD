# 在线资源下载支持（本地 + 在线共存）

> 方案状态：已确认（2026-09-20），开始执行。
> 一句话：**在线下载 = 上传在线视频**——复用现有 hash 键 + labels + 后端判重机制，只是来源从用户本地文件变成 http URL。

## 一、目标

1. 支持在线图片/视频：按 http(s) URL 下载，与本地内置/用户上传**共存**；
2. 在线资源**后台静默下载**（不阻塞主题启动、不打断用户），下载完成后**用户可选**（出现在墙纸选择列表）；
3. 配置 json **内置**在主题包内、随分发（别人安装也自动下载）；不用纠结源，来源由 EIGHTfs 提供（hash 由用户以后指定在线视频）。

## 二、与现有 hash 机制完全对齐

用户确认语义（关键）：

| 现有上传机制 | 在线下载机制（同一套） |
|---|---|
| 后端算 SHA-1 → `id` = 40 位 hex | 配置文件**显式给 hash 作主键**（内容寻址，下载后校验一致） |
| 磁盘文件名 = `<hash>.<ext>` | 磁盘文件名 = `<hash>.<ext>`（存 `wallpapers/online/` 子目录） |
| `labels[hash] = 原始文件名去后缀` | 下载完成后写 `labels[hash] = 配置 name 去后缀` |
| 前端显示 label（文件名不带后缀） | 前端显示 label（文件名不带后缀） |
| 后端 existsSync 判重（同内容不重复落盘） | 后端 existsSync 判重（已下载跳过） |

> `labels.json` 是 `{hash: 文件名}` 键值对；前端显示文件名、后端用 hash 判断是否重复——在线资源完全沿用。

## 三、配置格式（lib/online-sources.json，内置随主题分发）

```json
{
  "_comment": "在线资源：hash 为主键（40 位 hex，内容寻址），name 为显示文件名（带后缀，前端去后缀显示），url 为下载地址。主题启动时后台静默下载缺失项。",
  "sources": {
    "<sha1-hex-40>": { "name": "示例视频.mp4", "url": "http://example.com/a.mp4" },
    "<sha1-hex-40>": { "name": "示例图片.png", "url": "http://example.com/b.png" }
  }
}
```

## 四、数据流

```
lib/online-sources.json（内置配置）
   │ 主题 apply 时（后台，不 await）
   ▼
downloadOnlineSources() 遍历 sources：
   ├ 目标 = wallpapers/online/<hash><ext>
   ├ 已存在（<hash><ext>） → 跳过（幂等，不重启重复下载）
   ├ 缺失/未完成 →
   │   ① 有 <hash><ext>.part → 断点续传：取 part 大小作偏移，请求带 Range: bytes=<offset>-
   │        ├ 响应 206 → 追加写入 part
   │        ├ 响应 200（服务器不支持 Range）→ 截断 part 从头下载
   │        └ 响应 416（偏移超文件）→ 从头下载
   │   ② 无 .part → 从头流式下载写入 .part
   │   ③ 完成 → SHA-1 校验 == 配置 hash（不一致：删除 .part + 告警日志，不出现在线项）
   │   ④ 一致 → rename .part 为 <hash><ext> → labels[hash] = name 去后缀
   │   ⑤ 中断（超时/断网/重启）→ 保留 .part，下次启动从断点继续（断点续传）
   └ 并发池（默认 3）+ 单文件超时 + 重试，失败静默记录（.part 保留供续传）
   ▼
handleList() 合并 wallpapers/online/ 条目进 /wallpapers/list（同 id 顶层优先去重）
   ▼
client loadCustomWallpapers() 照常 push → 用户在壁纸/选择面板可选
```

> **断点续传要点**：
> - 下载中状态以 `<hash><ext>.part` 存在与否标记；`.part` 是「下载未完成」标志，`<hash><ext>` 是「已校验完成」标志；
> - 续传：`Range: bytes=<part已下载字节数>-`；服务器 206 继续追加、200/416 从头重下；
> - SHA-1 校验对象是**完整文件内容**：续传场景对「既有 part 内容 + 新追加内容」整体逐块 update（先回读 part 已存字节累计 hash，再继续新块），保证断点续传后校验仍正确；
> - 校验通过才 rename 落定；任何失败保留 .part 供下次续传，不产生半成品正式文件。
```

## 六、风险与边界

| 项 | 处理 |
|---|---|
| 下载失败/断网 | 单文件失败静默记录日志，不影响启动与其余项；下次重启自动重试 |
| 大文件耗尽磁盘 | 沿用 `uploadLimitBytes` 动态上限；超限跳过并告警 |
| hash 不匹配 | 删除 .part、日志告警、不出现在线项（防错源/篡改） |
| 同内容重复 | 磁盘判重天然幂等；与用户上传同 hash 时顶层优先展示一份 |
| 下载占带宽 | 并发池限 3，启动后台跑不阻塞 |
| 内置 assets | 保留不动；未来换内置只需把文件移到在线配置，机制不变（用户已确认） |
