# 配色对照页（theme-swatch.html）设计

> 日期：2026-09-21
> 状态：已实现（可交互版）
> 位置：`preview/theme-swatch.html`（预览服务器 `/theme-swatch.html` 访问）
> 配套接口：`preview/start-preview.mjs` 新增 `POST /api/theme-save` + `GET /generated/*`

---

## 一、用户需求（原话提炼）

1. **左右下拉框各选基底对比**——左右两列可自由选择基底（当前流萤/知更鸟两套），自由选择对比，以后可以更多基底
2. **6 种配色改成按钮点击就能选择**——组件模拟区每个元素（如「主要按钮」当前是礼服紫）点击后可任意选择颜色
3. **结果落盘成 css**——选好的配色导出为 CSS 文件落盘

## 二、用户决策

| # | 决策 | 含义 |
|---|------|------|
| 1 | 先 preview/generated/ | 导出 CSS 先落盘到 `preview/generated/<基底名>-<列>.css`（不入库），作为配色方案沉淀 |
| 2 | 好看的替换成正式版 | 用户认为导出的配色好看时，再把对应 CSS 替换进正式主题（identity.js / tokens.js） |
| 3 | 流萤暂存仅对照 | 流萤配色在基底池保留作对照选项，不启用 |

## 三、架构设计

```

│    robin   知更鸟（当前基底） bg=#100e1c          │

│  │ 组件模拟   │        │ 组件模拟   │               │
│  └────┬─────┘        └────┬─────┘               │
│       │ 点击组件            │                     │
│       ▼                    ▼                     │
```

## 四、核心数据结构

### 4.1 基底池 BASES（**动态读取，不写死**）

**基底来源 = css 文件**（前端不再内嵌 BASES 对象）：
- 内置基底：`preview/bases/*.css`（robin.css / robin-bright.css / firefly.css / robin-blue.css）
- 用户导出：`preview/generated/*.css`（「导出 CSS」自动落盘，回读即新基底）
- 页面加载 `GET /api/theme-bases` → 服务端扫两个目录解析 css → 返回基底清单 → 前端 `loadBases()` 填充 `BASES`

**基底 css 格式**（`--swatch-*` 变量）：

```css
/* 基底名注释 */
:root {
  --swatch-label: "知更鸟·蓝（对照）";   /* 下拉显示名（可选） */
  --swatch-bg: #3E2F66;                /* 背景色 */
  --swatch-bgSoft: #2a2148; --swatch-bgLayer: #362a56;
  --swatch-skin: #E8F4FA;              /* 6 色：肤色/发色/瞳色/灰白/紫/金 */
  --swatch-hair: #F2A7B8; --swatch-eye: #7CC8E8;
  --swatch-white: #D8EAF4; --swatch-purple: #3B89C4; --swatch-gold: #E2C05A;
  --swatch-btn-primary: #7CC8E8;       /* 组件色（缺省按 6 色映射） */
  --swatch-btn-secondary: #3B89C4; --swatch-chip-active: #E2C05A;
  --swatch-text-primary: #E8F4FA; --swatch-text-dim: #F2A7B8;
  --swatch-text-tertiary: #9E8FC8; --swatch-gold-glow: #E2C05A;
}
```

**加新基底**：放一个 css 文件进 `preview/bases/`（或对照页导出到 `preview/generated/`），下拉自动出现，无需改任何 JS。同 hex 自动去重（避免循环换色卡在同色）。

**加新基底**：只往 `BASES` 追加一个对象（label/bg/swatches/comps/cardStyle/note），下拉框自动出现，无需改其它代码。

### 4.2 交互状态

```js
const state = { L: { base: "robin", comps: {}, bg: null }, R: { base: "firefly", comps: {}, bg: null } };
// comps: { role: { style, text } }——用户点击换色后的覆盖记录；未点过则用基底默认；bg: 列背景色覆盖
```

- 切换下拉框 → 重置该列 comps → 重渲染（renderCol）
- 点击组件 → cycleColor(side, role) 在**当前基底 swatches（6 色）**中循环切换（背景类换 background+对比文字色、文字类换 color、gold-glow 同步 text-shadow）→ 重渲染
- 点击背景块（组件区右侧 `.bg-block`，含当前背景色圆点）→ cycleBg(side) 在**当前基底 6 色**中循环换背景（不再用写死色池）；点列空白同样触发
- 每列标题栏「⬇ 应用此列为正式基底」按钮 → applyCol(side)：打包该列 6 色 + bg → POST `/api/theme-apply`

### 4.3 导出 CSS

- `genCssFor(side)`：生成 `:root` 块——含 `--swatch-label`（基底名）、6 色（skin/hair/eye/white/purple/gold）、bg/bgSoft/bgLayer、7 个组件 `--swatch-<role>`（**格式兼容 /api/theme-bases 回读，导出即成为新基底**）
- 「导出 CSS」按钮 → 两列各 POST `/api/theme-save`（name = `<基底id>-L/R`）→ 落盘 `preview/generated/`
- **不做** `--dsw-*` 全量导出（那是正式主题的令牌），导出的是**当前交互配置**（swatch 变量），供用户看效果后决定是否转正式

### 4.4 一键应用为正式基底（theme-apply）

- **每列独立应用按钮**（用户决策：两边都改了不歧义，点哪列应用哪列）：`applyCol(side)` 从该列 comps 提取颜色，映射规则：

  | 组件 role | 6 色键 | 说明 |
  |-----------|--------|------|
  | text-primary | skin | 主文字 |
  | text-dim | hair | 次文字 |
  | btn-primary | eye | 主按钮/品牌 |
  | chip-active | white | 对比/灰白 |
  | btn-secondary | purple | 次要/装饰 |
  | gold-glow | gold | 高亮/边框 |
  | 列背景 | bg/bgSoft/bgLayer | 背景层 |

- `POST /api/theme-apply`：body `{ name, colors }` → 服务端生成 identity.js `--ff-theme-*` 段 + tokens.js 完整 `TOKENS`（6 色推导全部令牌）→ 旧值备份到 `preview/generated/backup-<ts>/` → 写盘 → 自动 `build.cjs` → 预览立即生效
- **应用结果**：正式基底（identity.js + tokens.js）被改写，原值可备份恢复；对照页只改预览不落盘（除显式导出/应用）

## 五、后端接口（start-preview.mjs）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/theme-save` | POST | body `{ name, css }` → `preview/generated/<name>.css`（name 去非法字符，限 60 字符；body 限 512KB） |
| `/api/theme-apply` | POST | body `{ name, colors }` → 生成 identity.js `--ff-theme-*` 段 + tokens.js 完整 `TOKENS` → 旧值备份 `preview/generated/backup-<ts>/` → 写盘 → 自动 build |
| `/api/theme-bases` | GET | 扫 `preview/bases/*.css` + `preview/generated/*.css` → 解析 `--swatch-*` 重建基底清单（下拉动态源） |
| `/generated/*` | GET | 回读导出的 CSS 文件（防目录穿越：normalize 后校验前缀） |

## 七、后续扩展（预留）

2. **好看转正式**：导出 CSS 经用户确认后，把对应色值替换进 `identity.js` 的 `--ff-theme-*` 与 `tokens.js` 的 `--dsw-*`
3. **全量令牌导出**：可扩展「导出 --dsw-* 全量」模式（当前只导出交互 swatch 变量）
4. **回读/重置**：已导出方案可在页面下拉「已存方案」加载恢复（预留，未实现）
