## 〇.5、目录复制机制（按资源 json 整目录复制，只复制一次）

> 2026-09-21 更新：由「整目录搬走」改为「整目录**复制**」——link 安装下安装目录=工作区同一份，
> 搬走删源会把工作区素材搬空；复制语义下仓库根永远保留素材（分发干净副本），数据目录获得运行副本。

- **驱动源 = lib/sources.json 的 `dirs` 字段**：`{ "<仓库根目录名>": "<真实数据子目录名>" }`。
  当前为 `{ "music": "music", "wallpaper": "wallpaper" }`——**以后加目录只改 json 的 dirs，不用改代码**。
- **动作 = 整目录复制**（不是按资源 json 逐个搬）：插件 apply 时（lib/bootstrap.js）把仓库根
  `music/`、`wallpaper/` **整个目录**递归复制到 `$DSH_HOME/theme-mediascape/<dst>/`（已存在文件跳过，
  仓库根保留不删源；复制天然兼容跨设备，无需 rename/EXDEV 降级分支）。
- **只复制一次（幂等）**：目标目录已存在且非空 → 视为已复制过（或用户预置），跳过不重复复制。
- 复制后，上传/在线下载/列表全部落在真实数据目录；仓库根保留素材（分发时随仓库自带，首启复制一次）。

## 一、新目录架构（真实数据目录）

```
.dsh/theme-mediascape/
├── wallpaper/                  ← 壁纸（图片+视频）落盘目录
│   ├── <sha40>.mp4 / .png / .jpg…
│   ├── online/                 ← 在线下载子目录（sources.json kind=wallpaper）
│   └── wallpaper.json          ← hash → 显示名 映射（labels 改名，含说明头）
└── music/                      ← 音乐落盘目录
    ├── <sha40>.mp3
    ├── <封面>.png
    └── music.json              ← hash → {音乐文件名, 封面文件名}（含说明头）
```

- 仓库 `lib/sources.json` = 在线资源清单（hash → {name, url, kind}），启动自动下载分流
- 仓库 `wallpaper/`、`music/` 表意 json = 空 JSON + 说明（结构示范，非真实数据）
- **所有资源（壁纸/音乐/开屏）build 不再内嵌**，运行时 API 拉取
